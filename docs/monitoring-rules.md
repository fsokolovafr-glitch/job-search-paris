# Правила мониторинга — версия 2

Источник: уточнение пользователя 2026-09-28. Новое ограничение заменяет старый обход
Found/Checked/крупных компаний: **только LinkedIn Jobs, Indeed, Welcome to the Jungle**.

- Искать все подходящие маркетинговые вакансии во Франции. Shortlist используется
  для ★ приоритетных компаний, не создаёт отдельные поисковые запросы и обходы сайтов.
- Ровно три площадки, по шесть фраз на каждую: 18 логических поисковых запросов.
  Результатов — до 20 на запрос; максимум 60 страниц вакансий за запуск по умолчанию.
  При сетевых ошибках допустимы до трёх попыток, без потери предыдущих результатов.
- Brave API используется только для поиска ссылок. Читать разрешено лишь HTTPS-карточки
  вакансий разрешённых доменов. Проверять разрешение ДО запроса и каждого редиректа.
  Не открывать сторонние сайты, даже если ссылка находится на разрешённой площадке.
- Не обращаться к компаниям в shortlist/backlog по их карьерным ссылкам.
  Сохранённые старые сторонние ссылки — справочные данные, не очередь проверки.
- Не открывать вакансии applied=true или application_status=rejected. Компании
  rejected/paused исключать из результатов. Не отправлять заявки и сообщения.
- Проверять структурированное объявление, название роли, работодателя, страну и срок.
  Заголовок поисковой выдачи не является основанием пропустить страницу вакансии.
- LIVE: единственное подходящее объявление с неистёкшим сроком. CLOSED: 404/410
  исходной ссылки либо истёкший validThrough того же объявления. UNKNOWN: ограничения
  доступа, редирект за разрешённую область, ошибки сети, отсутствующая/неоднозначная
  разметка. Отсутствие вакансии в выдаче само по себе не означает CLOSED.
- Не изменять исходный URL при запросе; ключ для удаления tracking-дублей хранить отдельно.
- Отчёт: новые → закрытые → повторно открытые → требует проверки → статистика → источники.
  В статистике считать запросы и страницы, а не «проверенные компании».
- Mock никогда не изменяет рабочие data/jobs.json и историю. Каждый mock-отчёт маркировать.
- Расписание пока сохраняет исходный cron; точные 48 часов им не гарантируются.

Исходный Schedule Task не предоставлен. Правила основаны на сообщениях пользователя,
а не на дословном копировании неизвестного задания.
