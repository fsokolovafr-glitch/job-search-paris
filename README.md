# job-search-paris

Мониторинг маркетинговых вакансий во Франции для Krolik. Python 3.9+, стандартная библиотека.

[Job Search Pipeline](dashboard/index.html) — отдельный статичный HTML-артефакт.
Скачайте и откройте в браузере. Его данные внесены вручную и не синхронизируются с монитором.
Статусы и ссылки в нём не являются результатом текущего запуска программы.

## Architecture

```text
Monitoring → SQLite transaction → JSON exports + Markdown reports
```

**SQLite (`data/job-search.db`) — источник истины после первого импорта.**
Монитор читает вакансии, компании и историю из SQLite. JSON состояния служит экспортом
для совместимости. `data/config.json` остаётся входной настройкой поиска.

## Структура

```text
data/
  job-search.db              # основное хранилище
  jobs.json                  # экспорт вакансий и статусов заявок
  companies-shortlist.json   # первоначальный импорт, затем экспорт компаний
  job-tracking.json          # экспорт истории запусков
  companies-backlog.json     # справочный архив, не мониторится
  applications-log.csv       # ручной журнал, без автоматического импорта
  config.json                # настройки поиска
scripts/
  history_store.py           # SQLite, события, миграция, аналитика
  monitor.py                 # поиск и проверка
  check-jobs.py              # точка входа
  job-analytics.py           # аналитика
  update-tracker.py          # проверка SQLite и восстановление экспортов
  parse-jobs.py              # разбор сохранённого HTML
reports/                     # Markdown и JSON каждого запуска
dashboard/index.html         # независимый ручной снимок
.github/workflows/           # мониторинг и CI
```

Таблицы SQLite:

- `companies`: компании, приоритеты и исключения.
- `jobs`: текущий подтверждённый статус, даты, данные вакансии и заявки.
- `job_events`: история изменений вакансий.
- `monitoring_runs`: результаты запусков и ссылки на отчёты.

## Vacancy lifecycle

`JOB_DISCOVERED → JOB_UPDATED → JOB_CLOSED → JOB_REOPENED`

- `JOB_DISCOVERED`: впервые обнаруженная вакансия.
- `JOB_UPDATED`: изменилась сохранённая структурированная информация о вакансии.
- `JOB_CLOSED`: подтверждено закрытие (404/410 или истёкший срок).
- `JOB_REOPENED`: закрытая вакансия снова подтверждена как LIVE.
- `JOB_STATUS_CHANGED`: другое изменение подтверждённого статуса.

Записи не удаляются. Отсутствие вакансии в поисковой выдаче не доказывает закрытие.
403, сетевые ошибки и неоднозначная разметка дают UNKNOWN; предыдущий подтверждённый
статус сохраняется. Пропущенная проверка не меняет `last_seen`, UNKNOWN тоже не означает
новое подтверждение. Неизменившаяся вакансия не создаёт JOB_UPDATED.

## Deduplication

Новые ключи `job_key` — SHA-256 от однозначно сериализованной тройки компания, название,
нормализованный URL. Названия нормализуются по Unicode, регистру, пробелам и диакритике:
`Société Générale` и `Societe Generale` совпадают. У URL удаляются tracking-параметры
и фрагмент; регистр пути сохраняется, поскольку он может иметь значение.

Известная каноническая ссылка сохраняет свою запись и историю при изменении названия.
Старые ключи сохраняются при миграции. Одна роль на разных площадках пока может
считаться несколькими вакансиями: общего идентификатора работодателя нет.

## Запуск

Из корня репозитория:

```sh
python3 -m unittest discover -s tests -v
python3 scripts/check-jobs.py --mode mock --output work/demo
python3 scripts/update-tracker.py --root work/demo
python3 scripts/job-analytics.py --db work/demo/data/job-search.db --trend 30d
```

Mock работает офлайн в отдельной папке. Повторный запуск использует её SQLite.
Для live нужен `BRAVE_SEARCH_API_KEY` в окружении:

```sh
python3 scripts/check-jobs.py --mode live --dry-run
python3 scripts/check-jobs.py --mode live
python3 scripts/update-tracker.py
```

Dry-run выполняет сетевые запросы, но использует временную копию SQLite.

## Hiring Intelligence

```sh
python3 scripts/job-analytics.py
python3 scripts/job-analytics.py --trend 30d
```

Вывод: Companies tracked, Active jobs, Closed jobs, Market Activity,
Top Hiring Companies, Hiring Momentum, Reopened Roles, Employer Activity Score.
Те же разделы добавляются в Markdown-отчёт.

- Период событий: от текущего времени минус N дней до текущего времени включительно.
- Net growth = обнаружения минус закрытия; повторные открытия показываются отдельно.
- Momentum компании = обнаружения + повторные открытия − закрытия за период.
- Top Hiring Companies = число сейчас активных вакансий.
- Activity score = активные вакансии + события повторного открытия + исторические
  обнаружения за всю историю до текущего времени. Компании без активных вакансий
  тоже участвуют в рейтинге.

Это показатели наблюдаемой выборки, а не всего рынка. Импорт старого состояния не
создаёт вымышленных обнаружений. Снимок активных вакансий отражает последнее
подтверждённое состояние, а не гарантированную доступность прямо сейчас.

## Ограничения поиска

Разрешены только карточки LinkedIn Jobs, Indeed и Welcome to the Jungle.
Сайты работодателей, произвольные ATS и переходы на них блокируются до запроса.
Это сознательное ограничение для предсказуемого объёма мониторинга. Внешние ссылки
в ручном HTML-артефакте не расширяют разрешения программы.

Brave Search API выполняет 18 логических запросов (6 фраз × 3 платформы), независимо
от количества компаний. Максимум 60 страниц за запуск; повторы запросов возможны.
Shortlist задаёт приоритеты и исключения. JS-only страницы и отсутствие подходящей
JobPosting-разметки дают UNKNOWN. Полнота поиска не гарантируется.

## Migration from JSON tracking

Первый запуск один раз импортирует `jobs.json`, компании и старую историю запусков.
Существующие записи SQLite сохраняют статусы и ключи; JSON дополняет данные заявок.
Далее SQLite становится авторитетным источником. Изменение JSON не меняет состояние
монитора. Старые команды сохраняются, но ручное редактирование экспортов заменяется
обновлением базы. JSON можно восстановить командой `update-tracker.py`.

Для статуса заявки:

```sh
python3 scripts/update-tracker.py --job-url 'https://www.linkedin.com/jobs/view/123' --application-status applied
```

Допустимы `not_applied`, `applied`, `rejected`. CSV остаётся ручным журналом.
Для изменения компаний после импорта используйте SQLite и затем обновите экспорты;
специализированного редактора компаний пока нет. Перед изменением базы сделайте копию.
Команды мониторинга сериализуются через lock; не запускайте ручное изменение базы
одновременно с монитором.

## GitHub Actions

Actions secret: `BRAVE_SEARCH_API_KEY`. Variable: `MONITOR_ENABLED=true` для включения.
Включение и успешный live-запуск требуют отдельной проверки; тесты работают без ключа.
Workflow сохраняет SQLite, JSON и отчёты через встроенный GITHUB_TOKEN.
Cron `0 10 */2 * *` — 10:00 UTC по нечётным дням месяца, не строгие 48 часов.
При частичной проверке данные сохраняются, затем запуск отмечается ошибкой.
При ошибке push результаты доступны в recovery artifact.

Транзакция SQLite атомарна; JSON и отчёты записываются после неё. При прерывании
экспорта восстановите JSON через `update-tracker.py`; отсутствующий отчёт требует
восстановления из сохранённого результата запуска/артефакта.
