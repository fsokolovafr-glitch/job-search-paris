# Правила мониторинга

Источник: задание пользователя от 2026-09-28. Оригинальный текст Schedule Task
не предоставлен: это реализация перечисленных требований, не дословная копия.

1. **Found — not applied:** проверять сохранённые вакансии с `applied: false`.
2. **Checked:** проверять сохранённые вакансии и искать новые по целевым ролям во Франции.
3. **Крупные компании:** для Track A/B с известной численностью ≥1000 включать
   поиск новых вакансий и отдельную строку отчёта. Размер компании не угадывать.
4. **Исключения:** backlog (в том числе заявленные 75 компаний Track A), компании
   `rejected`/`paused`, вакансии `applied: true` или `application_status: rejected`.
5. **Как:** WebSearch (Brave API), затем web fetch (HTTP GET), проверка JobPosting.
   Поисковый сниппет сам по себе не подтверждает LIVE. Совпадение работодателя
   точное после нормализации; дополнительные варианты задаются `aliases`.
6. **LIVE:** единственный подходящий JobPosting с целевой ролью, страной и работодателем,
   срок которого не истёк. **CLOSED:** HTTP 404/410 на исходном URL либо истёкший
   validThrough соответствующей вакансии. HTTP 200 без объявления, редирект,
   403/429/5xx, сетевой сбой и неоднозначные данные — **UNKNOWN**.
7. При UNKNOWN последнее подтверждённое `status` сохраняется; текущая неопределённость
   записывается в `last_check_status` и `evidence`. Статистика «живых» считает только
   подтверждения текущего запуска. «Проверено компаний» включает попытки с частичным результатом.
8. Не создавать повторную вакансию для того же нормализованного URL; удалять только
   tracking-параметры, сохранять идентификаторы вакансий в query. Повторное открытие
   учитывать отдельно. «Закрыто» повторно не сообщать при неизменном CLOSED.
9. Формат: новое → закрыто → повторно открыто → требует проверки → крупные компании
   → статистика → все использованные ссылки. Дневной файл показывает последний запуск;
   отдельные timestamp-файлы и `check_history` сохраняют каждый запуск.
10. Mock-данные сохранять только в отдельную output-папку и явно маркировать MOCK.

Пустой поиск не доказывает отсутствия вакансий. Полнота ограничена индексом,
ключевыми словами, глубиной поиска и читаемостью страниц. Настоящий список и точные
правила исходной задачи нужно сверить после предоставления владельцем.
